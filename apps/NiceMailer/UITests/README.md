# Scripted UI tests

Each `*.uiscript` file is a scenario played by the app itself in **UI script mode**: it sends simulated keys and mouse clicks to its own window and checks the resulting state. Run them all with `make ui-test` (or `scripts/ui-test.sh scenario.uiscript` for one: a bare name is looked up in `UITests/`, and a scenario that does not exist fails rather than passing with nothing played). `NICEMAILER_UI_BIN=<executable>` plays them with another build of the app, such as `~/Applications/NiceMailer.app/Contents/MacOS/NiceMailer` (`make bundle`).

For each scenario, `scripts/ui-test.sh`:

1. creates a fresh data directory with fake mail (`nicemailer seed --threads 300 --seed 1`, account `perso`) and imports `fixtures/sample.mbox` (account `fixture`, address `me@example.com`: an HTML newsletter with a link, a link around its logo, a phone number and three attached files, a logo shown by its HTML, two remote images and a tracking pixel and a one-click List-Unsubscribe header, a thread with a link, a long mail (text and HTML), a four-message thread with quotes, signatures and a mobile mention);
   A scenario may add mail of its own: `fixtures/<scenario>.mbox`, when it exists, is imported into the same account for that scenario only, so the mail the others count stays the same;
   A scenario may have settings of its own: `fixtures/<scenario>.config.toml`, when it exists, is the `config.toml` of its core;
2. starts a core on it;
3. runs the app with `NICEMAILER_UI_SCRIPT=<scenario>`, `NICEMAILER_EXPORT_DIR=<temporary directory>` and `-AppleLanguages (en)` (English messages whatever the machine's language);
4. prints `PASS` or `FAIL` with the failed lines, then removes the data directory.

Results go to `apps/NiceMailer/.build/ui-test/<scenario>/`: `result.txt` (every check), the snapshots asked by `snap`, and `fail-line-N.png` for each failed check.

## The app stays out of your way

In UI script mode the app is never activated (no Dock icon, no keyboard focus), its window is borderless, transparent and off screen, it uses its own emptied preferences domain, and it exports into the temporary directory. You can keep working while the tests run: your typing never reaches it.

## Script language

One command per line; `#` starts a comment.

| Command | Effect |
| --- | --- |
| `key K` | one key: a character (`j`, `J`, `;`, `*`…), `esc`, `ret`, `del`, `up`, `down`, `space`, `shift-space`, `shift-up`, `shift-down`, `cmd-ret`, `shift-cmd-ret`, `tab`, `shift-tab`, `alt-cmd-b`, `alt-cmd-f`, `shift-cmd-a`, the editing keys `left`, `right`, `alt-left`, `alt-right`, `cmd-left`, `cmd-right`, `home`, `end`, `fdel` (forward delete), `alt-del`, `cmd-del`, the selecting keys `shift-left`, `shift-right`, `shift-alt-left`, `shift-alt-right`, `shift-cmd-left`, `shift-cmd-right`, `shift-cmd-up`, `shift-cmd-down` (and `cmd-up`, `cmd-down`), or `ctrl-X` or `cmd-X` |
| `type TEXT` | each character of TEXT as a key |
| `axselect START LENGTH` | selects a range of the reply (UTF-16 units) through the accessibility API, as another app (Kerlig) would |
| `axreplace TEXT` | writes TEXT in place of the reply's selection through the accessibility API |
| `openurl URL` | gives URL to the app as macOS would (a deep link `nicemailer://m/<id>`); `openurl clipboard` opens the first `nicemailer://` URL of the private pasteboard |
| `appearance dark` | the app's appearance, `dark`, `light` or `system` (the Mac's): for this app only |
| `addressbook ACCESS` | what macOS answers about Contacts: `authorized`, `denied`, `unavailable` (a bare executable), `undetermined`; the book is always the scenario's own (`FixtureAddressBook.sample`: Alice and Bob), never the user's |
| `mailbox FOLDER` | "Change Mailbox…" with FOLDER, relative to the scenario's data directory (`mailboxes/old`, `mailboxes/early`, `mailboxes/newer`, `mailboxes/empty`, made by `scripts/ui-test.sh`): the folder is checked and upgraded with the real CLI (`NICEMAILER_CLI`), but the switch is only recorded in `mailbox_switched`, never made |
| `upgrade FROM TO` / `upgrade off` | Writes `core-upgrading.json` in the scenario's data directory, with the app's own pid, as a core does before migrating its database: the app shows its "upgrading" screen and waits (`AppModel.waitForUpgrade`). `upgrade off` removes it, and the wait ends |
| `files A, B` | the files the open panel of ⇧⌘A answers next, by name, from `fixtures/files` (the panel itself is never shown) |
| `clipfiles A, B` | file URLs of `fixtures/files` on the private pasteboard, as the Finder's ⌘C puts them |
| `clipboard TEXT` | puts TEXT (`\n` for a line break) on the pasteboard ⌘V reads: a private one, never the user's clipboard |
| `click TARGET [cmd] [shift]` | a click on a row, with modifiers |
| `dblclick TARGET` | a double-click |
| `resize WxH` | window size (default 1400×900) |
| `snap NAME` | PNG of the window (a web view, drawn in another process, appears empty: check it with the `html_*` fields) |
| `wait MS` | pause |
| `expect FIELD OP VALUE` | check a state field; `OP` is `=`, `!=`, `~` (contains), `!~` (does not contain), `>` or `<`; waits up to 5 s for the condition |

Targets: `thread:N` (N-th row of the mail list, from 0), `picker:N`, `screen:N` (row of the contacts, history, tags or groups screen), `folder:NAME` (folder column of the current view, 3-column layout), `attachment:N` (N-th attachment tile of the text reader), `reader:unsubscribe` (the unsubscribe button of the title line), `format:text`, `format:html`, `format:images` (the words of the display switch of the title line), `reader-link:N` (N-th header or "···" line of the text reader), `reader-sender:N` (the sender's address of the N-th unfolded message of the text reader), `status:account`, `status:folder`, `status:attributes`, `status:m`, `status:s` and `status:v` (the blocks of the status bar), `status:target-ROLE` (a move target of the status bar in Quarantine: `status:target-inbox`, `status:target-deleted`…), `picker:header` (the input line of the open picker), `outside:panel` (a spot of the content, top-right, outside any open picker or menu), `menu:N` (N-th row of the open prefix menu or question), `compose:from`, `compose:to`, `compose:cc`, `compose:bcc`, `compose:subject` (the lines of the reply's headers), `compose:to-N` (the N-th address of a line, `compose:cc-0`…), `suggestion:N` (N-th suggested address), `compose:file-N` (N-th file attached), `chip:ID` (an attribute chip: `seen`, `from:0`, `not_from:0`, `to:0`, `not_to:0`, `text`, `subject`, `contains` for `/`, `after`, `before`…).

## Writing a new scenario

Make clickable rows targetable with `.uiTarget("kind-\(id)")` (no cost outside UI script mode), expose any new state the scenario needs in `Runner.state()`, then add a `.uiscript` file and a line to the table above.
