# Scripted UI tests

Each `*.uiscript` file is a scenario played by the app itself in **UI script mode**: it sends simulated keys and mouse clicks to its own window and checks the resulting state. Run them all with `make ui-test` (or `scripts/ui-test.sh scenario.uiscript` for one: a bare name is looked up in `UITests/`, and a scenario that does not exist fails rather than passing with nothing played). `NICEMAILER_UI_BIN=<executable>` plays them with another build of the app, such as `~/Applications/NiceMailer.app/Contents/MacOS/NiceMailer` (`make bundle`).

For each scenario, `scripts/ui-test.sh`:

1. creates a fresh data directory with fake mail (`nicemailer seed --threads 300 --seed 1`, account `perso`) and imports `fixtures/sample.mbox` (account `fixture`, address `me@example.com`: an HTML newsletter with a link, a link around its logo, a phone number and three attached files, a logo shown by its HTML, two remote images and a tracking pixel and a one-click List-Unsubscribe header, a thread with a link, a long mail (text and HTML), a four-message thread with quotes, signatures and a mobile mention);
2. starts a core on it;
3. runs the app with `NICEMAILER_UI_SCRIPT=<scenario>`, `NICEMAILER_EXPORT_DIR=<temporary directory>` and `-AppleLanguages (en)` (English messages whatever the machine's language);
4. prints `PASS` or `FAIL` with the failed lines, then removes the data directory.

Results go to `apps/NiceMailer/.build/ui-test/<scenario>/`: `result.txt` (every check), the snapshots asked by `snap`, and `fail-line-N.png` for each failed check.

## The app stays out of your way

In UI script mode the app is never activated (no Dock icon, no keyboard focus), its window is borderless, transparent and off screen, it uses its own emptied preferences domain, and it exports into the temporary directory. You can keep working while the tests run: your typing never reaches it.

## Script language

One command per line; `#` starts a comment.

| Command | Effect |
| --- | --- |
| `key K` | one key: a character (`j`, `J`, `;`, `*`…), `esc`, `ret`, `del`, `up`, `down`, `space`, `shift-space`, `shift-up`, `shift-down`, `cmd-ret`, the editing keys `left`, `right`, `alt-left`, `alt-right`, `cmd-left`, `cmd-right`, `home`, `end`, `fdel` (forward delete), `alt-del`, `cmd-del`, or `ctrl-X` or `cmd-X` |
| `type TEXT` | each character of TEXT as a key |
| `openurl URL` | gives URL to the app as macOS would (a deep link `nicemailer://m/<id>`); `openurl clipboard` opens the first `nicemailer://` URL of the private pasteboard |
| `addressbook ACCESS` | what macOS answers about Contacts: `authorized`, `denied`, `unavailable` (a bare executable), `undetermined`; the book is always the scenario's own (`FixtureAddressBook.sample`: Alice and Bob), never the user's |
| `clipboard TEXT` | puts TEXT (`\n` for a line break) on the pasteboard ⌘V reads: a private one, never the user's clipboard |
| `click TARGET [cmd] [shift]` | a click on a row, with modifiers |
| `dblclick TARGET` | a double-click |
| `resize WxH` | window size (default 1400×900) |
| `snap NAME` | PNG of the window (a web view, drawn in another process, appears empty: check it with the `html_*` fields) |
| `wait MS` | pause |
| `expect FIELD OP VALUE` | check a state field; `OP` is `=`, `!=`, `~` (contains), `!~` (does not contain), `>` or `<`; waits up to 5 s for the condition |

Targets: `thread:N` (N-th row of the mail list, from 0), `picker:N`, `screen:N` (row of the contacts, history, tags or groups screen), `folder:NAME` (folder column of the current view, 3-column layout), `attachment:N` (N-th attachment tile of the text reader), `reader:unsubscribe` (the unsubscribe button of the title line), `format:text`, `format:html`, `format:images` (the words of the display switch of the title line), `reader-link:N` (N-th header or "···" line of the text reader), `status:account`, `status:folder`, `status:attributes`, `status:m`, `status:s` and `status:v` (the blocks of the status bar), `picker:header` (the input line of the open picker), `outside:panel` (a spot of the content, top-right, outside any open picker or menu), `menu:N` (N-th row of the open prefix menu or question), `chip:ID` (an attribute chip: `seen`, `from:0`, `not_from:0`, `to:0`, `not_to:0`, `text`, `subject`, `contains` for `/`, `after`, `before`…).

State fields (see `Runner.state()` in `Sources/NiceMailer/UIScript.swift`): `screen`, `overlay`, `mode`, `location`, `flash`, `error`, `folder`, `account`, `thread_count`, `selected` (index), `selected_subject`, `selected_unread`, `selected_flagged`, `selected_tags`, `marked` (indices, comma-separated), `marked_count`, `search_origin` (where Escape goes back after a `/` search: `folder:ID`, `all:ROLE`, `everything`, or empty), `picker_query`, `picker_cursor` (position of the cursor in the typed text, in characters), `picker_selected` (the typed text is selected: typing replaces it), `picker_index`, `picker_count`, `picker_first` (the row Return would choose), `picker_rows` (every row of the open picker, in order, separated by ` | `), `picker_width` (width of the open picker panel, in points), `picker_first_detail` (its detail: "dd mm yy", "domain"…), `picker_hint` (the hint of the input line while nothing is typed), `screen_index`, `contacts_count`, `history_count`, `tags_count`, `groups_count`, `columns`, `reading` (one column: the mail fills the window), `status_position`, `sort`, `body_format`, `reader_subject`, `reader_offset`, `list_rows` (rows of the mail list that fit, for `ctrl-d` / `ctrl-u`), `list_filter`, `export_files`, `html_text`, `html_font_loaded`, `html_font_family`, `html_inline_drawn` (embedded `cid:` images drawn in the HTML page), `html_author_font` (font of the first `<font face>`), `html_table_width` (width of the first table with a `width`, in points), `html_csp` (the page carries its Content Security Policy), `html_offset` (scroll position of the HTML page after the last keyboard scroll), `font_size`, `row_height` (height of the selected row, as laid out), `reader_text` (text shown by the text reader), `reader_links` (its header and "···" links), `reader_folded` (folded messages), `reader_attachments` (attachment tiles of the text reader), `images_offered` (the open thread has remote images: the switch shows `images`), `tracking_pixels` (pixels removed by the core from the open thread), `remote_allowed` (remote images the HTML page may load), `remote_shown` (images handed to the web view since launch), `inline_shown` (embedded images served to the web view since launch), `remote_requests` (requests sent since launch, to a local stand-in that answers with a small PNG: nothing leaves the machine), `remote_blocker` (WebKit's block list of remote loads: `on`, `off` if WebKit refused it, `pending` before the first HTML page), `title_lines` (the reader's title line on 1 line, or the subject above the controls on 2), `pasteboard` (what the private pasteboard holds: a link copied with `l`), `resources_bundle` (where the fonts and translations were found), `unsubscribe` (`header:one_click`, `header:browser`, `header:mail`, `body:browser`, `done`, or empty: the unsubscribe offered for the open mail), `opened_file` (file or URL the app would have opened with ⌘-click, ⌘-Return or ⌘U; nothing is opened in UI script mode), `reader_folder` (folder shown next to the subject in "Everything", empty elsewhere), `sticky` (id of the selected mail kept in a filtered list it no longer matches, empty otherwise), `show_all` (`T`), `filters` (labels of the attribute chips, comma-separated), `menu_index` (row of the open menu highlighted with the arrows, empty if none), `menu_x` and `menu_y` (position of the first row of the open menu, window coordinates), `undo_count` (steps `z` can undo), `suspect` (sender of a move waiting for its confirmation, empty otherwise), `choice` (title of the question shown: a suspect move, a decision), `contact_addr` and `contact_decision` (address and decision of the contact under the cursor; a domain's decision after `@`).

## Writing a new scenario

Make clickable rows targetable with `.uiTarget("kind-\(id)")` (no cost outside UI script mode), expose any new state the scenario needs in `Runner.state()`, then add a `.uiscript` file and a line to the table above.
